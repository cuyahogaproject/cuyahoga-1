
**************************************************************
From version 1.7.0, Cuyahoga requires the .NET 4.0 Framework.
**************************************************************

Upgrading Cuyahoga

*****************************************************************************
ALWAYS BACKUP THE DATABASE AND THE FILES ON THE SERVER BEFORE UPGRADING!
*****************************************************************************

If you are running Cuyahoga 0.8.2 or higher, you can upgrade to a new version 
by copying the new web files over the old files. The first user who accesses 
the site after upgrading is redirected to the upgrade page after logging in 
as administrator. Other users see a message that the site is being upgraded.

The upgrade page is always accessible for administrators at 
CUYAHOGA_WEB_ROOT/Install/Upgrade.aspx. You might need that in case you get 
a message that the site is being upgraded while you are the person who is 
going to perform the upgrade.

Don't forget to check your modules for upgrades via the module administration!

*****************************************************************************
SPECIAL NOTE: CONFIGURATION MOVED TO WEB.CONFIG
- The Castle configuration files in /Config (properties.config, facilities.config
  and services.config) are gone. Services are registered in code, and the settings
  are 'Cuyahoga.*' appSettings in Web.config.
- Copy your settings from the old /Config/properties.config:
    connectionString  -> Cuyahoga.ConnectionString
    nhibernateDriver  -> Cuyahoga.NHibernateDriver
    nhibernateDialect -> Cuyahoga.NHibernateDialect
    smtpHost, smtpPort, smtpUsername, smtpPassword, emailEncoding
                      -> Cuyahoga.SmtpHost, Cuyahoga.SmtpPort, ...
    tempDir           -> Cuyahoga.TempDir
  Put them in Web.config, or in a Web.local.config next to Web.config that
  overrides the appSettings of Web.config (see the comment in Web.config).
- Custom changes in services.config have to move to code (Windsor registrations).
- Remove the /Config folder.
- Cuyahoga uses Castle Windsor 6, Castle.Core 5 and log4net 2. Custom modules that
  use the container directly: AddComponent and the kernel indexers (kernel[typeof(X)],
  kernel["key"]) don't exist anymore; use Register(Component.For<X>()...) and Resolve.

*****************************************************************************
SPECIAL NOTE: NHIBERNATE SESSIONS AND TRANSACTIONS
- The Castle NHibernate and AutoTx facilities have been replaced with
  Cuyahoga.Core.Persistence. When you keep your own Web.config, replace the
  NHibernateSessionWebModule entry (httpModules and system.webServer/modules) with
    <add name="NHibernateSessionModule" type="Cuyahoga.Web.HttpModules.NHibernateSessionModule, Cuyahoga.Web" />
- Custom modules: replace 'using Castle.Facilities.NHibernateIntegration;' and
  'using Castle.Services.Transaction;' with 'using Cuyahoga.Core.Persistence;'.
  ISessionManager, [Transactional] and [Transaction] work as before.
- Remove Castle.Facilities.AutoTx.dll, Castle.Facilities.NHibernateIntegration.dll
  and Castle.Services.Transaction.dll from the bin folder.

*****************************************************************************
SPECIAL NOTE: NHIBERNATE 5
- Cuyahoga uses NHibernate 5.5. NHibernate 5 only supports generic collections,
  so the collections of the domain classes are generic now (for example
  Node.ChildNodes is IList<Node> and Section.Settings is IDictionary<string, string>).
- Custom modules: map collections with IList<T>, ISet<T> or IDictionary<TKey, TValue>
  instead of IList, Iesi.Collections.ISet or IDictionary.
- The indexer of a generic dictionary throws when a key doesn't exist, where the
  old IDictionary returned null. Read section settings and connections with
  Section.Settings.GetValueOrDefault("NAME") (using Cuyahoga.Core.Util).
- Web.config needs a binding redirect for NHibernate to 5.5.0.0 (see the runtime
  section of the Web.config that comes with Cuyahoga).
- NHibernate.Caches.SysCache.dll comes from the NHibernate.Caches.SysCache package now.

*****************************************************************************
SPECIAL NOTE: THE FLASH AND FORUM MODULES HAVE BEEN REMOVED
- Browsers no longer run Flash, so the Flash module is no longer part of Cuyahoga.
  The Forum module has been removed as well.
- BEFORE copying the new files, remove all Flash and Forum sections and uninstall
  these modules via the module administration (Admin > Modules). After the
  upgrade the module files are gone, so they can't be uninstalled anymore.
  Uninstalling the Forum module deletes all forum posts, so back up the
  database first if you want to keep them.

*****************************************************************************
SPECIAL NOTE FOR USERS UPGRADING FROM 1.5.0 to 1.5.1
- If you have any custom modules in 1.5.0 that use NHibernate, you'll have to
  change these modules to be compatible with NHibernate 1.2.0, see
  http://www.hibernate.org/407.html for the migration guide. 
- Make sure you have a backup of Web.config and /Config/properties.config
- After extracting/copying the new files, copy the original properties.config 
  back and optionally change the new Web.config to match your original 
  Web.config. 
- By default, the installer only upgrades the core modules. After upgrading,
  check the module admin page at CUYAHOGA_WEB_ROOT/Admin/Modules.aspx and
  optionally upgrade the modules that have available updates.
*****************************************************************************

*****************************************************************************
SPECIAL NOTE FOR USERS UPGRADING FROM 1.0.x to 1.5.0 AND NEWER:
*****************************************************************************
- From version 1.5, Cuyahoga needs the .NET 2.0 framework. Make sure it is
  installed and your website is set to use the 2.0 framework (via IIS 
  administration).
- Make a backup of your old web.config. The new installation contains a new
  web.config without database connection info that has moved to 
  /Config/properties.config.
- Edit /Config/properties.config and copy the database connection info 
  (connectionString, nhibernateDriver and nhibernateDialect) from the 
  old web.config.

*****************************************************************************
Upgrading from versions pre-0.8.2
*****************************************************************************
Users upgrading from a pre-0.8.2 version must first update the database to
the 0.8.2 version. Use the scripts in /Database directory. If you don't know
which version you are running, you can find it in the cuyahoga_version table.
If the cuyahoga_version table doesn't exist yet, check the properties of the
Cuyahoga.Core.dll assembly (version tab).
